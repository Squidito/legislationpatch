# SECURITY.md — invariants and the gates that enforce them

This file explains **why** each security rule exists and **what enforces it**.
Documentation alone stops nobody — the gates do. Every invariant below is
paired with an automated check that fails loudly when the invariant breaks.

Context: static site on GitHub Pages (public repo — everything committed is
public), vanilla JS, no build step, no server. Data is generated by local
pipeline scripts and committed as JSON. There is no user-generated content;
the XSS surface is **ingested data** (Congress.gov text, quotes, rep names)
flowing into `innerHTML`.

## Invariants → gates

| # | Invariant | Why | Enforced by |
|---|---|---|---|
| 1 | No secret/API key in any tracked file — keys live in `.env` only | A GovInfo key was once hardcoded in scripts and shipped in a public repo; it took a full `git filter-repo` history purge + key rotation to clean up | `security-check.js` E1/E2 (pre-commit + CI); GitHub secret scanning |
| 2 | Every HTML page carries the CSP meta tag, un-weakened (no `unsafe-eval`, no external `script-src` hosts) | CSP is the backstop for any XSS that slips past escaping — an injected `<script src>` won't execute | `security-check.js` E3 (pre-commit + CI) |
| 3 | Every HTML page carries `<meta name="referrer" content="no-referrer">` | Don't leak reading habits to every outbound site | `security-check.js` E4 (pre-commit + CI) |
| 4 | Every `target="_blank"` link has `rel="noopener"` | Reverse tabnabbing — the opened page can navigate the opener | `security-check.js` E5 (pre-commit + CI) |
| 5 | `escHtml`, `portraitUrl`, `safeBioId` in `util.js` neutralize hostile input | Every `innerHTML` sink in the app assumes these three work; weakening one silently breaks all sinks at once | `test-security-helpers.js` — 91 hostile-payload assertions (pre-commit + CI + `npm test`) |
| 6 | Dynamic values reaching `innerHTML` pass through a sanitizer | Ingested data is the XSS vector here | `security-check.js` W1 (warning-level heuristic; template literals only) + invariant 5 + invariant 2 as blocking backstops |

## Where the gates run

1. **Pre-commit** — `scripts/hooks/pre-commit` (tracked; activated by
   `git config core.hooksPath scripts/hooks`, which `npm install` sets
   automatically via the `prepare` script). Catches problems before they
   reach the public repo.
2. **CI** — `.github/workflows/security.yml` runs the same checks on every
   push to `main`/`dev`. This is the layer that survives a re-clone, a
   missing hook, or `--no-verify`. A red ✗ on a commit means an invariant
   broke — fix it before anything else.
3. **`npm test`** — runs security-check + helper tests + validate locally.

## Bypass policy

- **Security errors (E1–E5) and helper-test failures: no sanctioned bypass.**
  Fix the finding. If a check is wrong (false positive), fix the *check* in
  `scripts/security-check.js` — with a comment explaining why — never the
  habit of skipping it.
- **Data-QA errors** (validate-batch): `SKIP_VALIDATE=1 git commit ...`
  skips only step 3 of the hook; the security gates still run.
- **`git commit --no-verify` skips everything, including security. Never use it.**
- **W1 XSS warnings**: after genuinely reviewing that every interpolated value
  is escaped upstream, annotate the line above the sink with
  `// xss-ok: <why it's safe>`. The annotation is greppable review debt.

## Known limitations (what the gates do NOT catch)

- W1 only sees template-literal interpolation (`${...}`). Concatenation-style
  sinks (`'...' + var + '...'`) are invisible to it — invariants 2 and 5 are
  the blocking defense for those, plus human review of any new `innerHTML`.
- The secret scan is pattern-based. A key with an unusual shape assigned to an
  unusually-named variable can slip through — GitHub secret scanning is the
  second layer, `.env`-only discipline is the first.
- `security-check.js` scans the **working tree** of tracked files, so a
  violation staged-then-unstaged before commit isn't distinguished; CI rescans
  the actual pushed tree and is authoritative.
